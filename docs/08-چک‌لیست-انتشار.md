# ۰۸ — چک‌لیست انتشار

این سند فهرست کارهایی است که **کد نیستند**: کلید، دامنه، حساب، و تنظیمات.
هر کدام یک بار انجام می‌شوند، ولی بدونشان انتشار ممکن نیست. ترتیب مهم است،
چون بعضی به بعضی دیگر وابسته‌اند.

وضعیت هر بند در تاریخ ۱۴ مرداد ۱۴۰۴ نوشته شده.

---

## ۱. کلید امضای اپ ✅ انجام شد (۳۰ مرداد ۱۴۰۵)

کلید در `~/keys/speakup-release.jks` ساخته شد و تنظیمات در
`~/.gradle/gradle.properties` نوشته شد. `assembleRelease` تست شد:
`BUILD SUCCESSFUL`، امضا با `apksigner verify` تأیید شد (v2 scheme،
گواهی `CN=SpeakUp`). حجم APK: ۴٫۱۶ مگابایت.

> ⚠️ نکته‌ی فنی: keytool جدید کیستور رو PKCS12 می‌سازه که رمز کیستور و
> رمز کلید باید یکی باشن — برخلاف فرض دو رمز جدا که پایین‌تر نوشته شده.

> 🔴 **یادت نره بک‌آپ بگیری** از `~/keys/speakup-release.jks` و
> `~/.gradle/gradle.properties` در یه جای امن خارج از این مک.

<details>
<summary>دستور اصلی (برای مرجع)</summary>

**چرا اول از همه:** سه چیز دیگر به آن وابسته‌اند و هیچ‌کدام تا این ساخته
نشود قابل نهایی شدن نیستند.

```bash
keytool -genkeypair -v -keystore release.jks -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
```

سپس این چهار خط را در **`~/.gradle/gradle.properties`** بنویسید — یعنی
فایل gradle در پوشه خانگی خودتان، **نه** `android/gradle.properties`:

> ⚠️ `android/gradle.properties` **داخل مخزن است و به گیت‌هاب می‌رود.**
> اگر رمز کلید امضا را آن‌جا بنویسید، رمزتان عمومی می‌شود. فایل پوشه
> خانگی هرگز در مخزن نیست و Gradle خودش هر دو را می‌خواند.

```properties
speakup.storeFile=/مسیر/امن/release.jks
speakup.storePassword=…
speakup.keyAlias=upload
speakup.keyPassword=…
```

تا وقتی این تنظیم نشده، `assembleRelease` نسخه **بدون امضا** می‌سازد و
کافه‌بازار نمی‌پذیردش. این عمدی است: build نباید بشکند، ولی نباید وانمود
هم بکند که خروجی قابل انتشار است.

> ⚠️ **این فایل را گم نکنید.** کافه‌بازار به‌روزرسانی اپی را که با کلید
> دیگری امضا شده باشد نمی‌پذیرد. گم شدنش یعنی انتشار اپ جدید و از دست
> رفتن تمام کاربران فعلی. یک نسخه پشتیبان آفلاین بگیرید.

## ۲. دامنه و HTTPS ⛔ انجام نشده

اپ در نسخه منتشرشده فقط HTTPS می‌پذیرد
(`app/src/main/res/xml/network_security_config.xml`) و build اگر نشانی
سرور https نباشد، عمداً شکست می‌خورد.

```bash
./gradlew :app:assembleRelease -Pspeakup.apiBaseUrl=https://api.speakup.ir/
```

- [ ] دامنه ثبت شود
- [ ] گواهی TLS (Let's Encrypt کافی است)
- [ ] سرور پشت nginx یا Caddy، نه Node مستقیم روی ۴۴۳

## ۳. سرویس پیامک ⚠️ کد آماده، حساب نه

کد در `backend/src/lib/sms.ts` است و تست دارد. آنچه مانده حساب و الگوست:

- [ ] حساب کاوه‌نگار و خرید خط خدماتی
- [ ] **هش SMS Retriever** را بگیرید (به کلید بند ۱ نیاز دارد):
  ```bash
  tools/sms_app_hash.sh release.jks upload ir.speakup.app
  ```
- [ ] الگو را در پنل ثبت کنید. خط آخر باید **دقیقاً** همان هش باشد:
  ```
  کد ورود اسپیک‌آپ: %token
  fsNl0lc7Swe
  ```
- [ ] متغیرهای محیطی سرور:
  ```
  SMS_PROVIDER=kavenegar
  KAVENEGAR_API_KEY=…
  KAVENEGAR_TEMPLATE=نام-الگو
  ```

> اگر هش اشتباه باشد **هیچ خطایی دیده نمی‌شود**؛ فقط کد خودکار پر نمی‌شود
> و کاربر باید دستی تایپ کند. حتماً روی یک گوشی واقعی تست کنید.

## ۴. متغیرهای محیطی سرور تولید

سرور اگر هرکدام از اینها اشتباه باشد عمداً بالا نمی‌آید — این محافظ
جای همین چک‌لیست را می‌گیرد:

```
NODE_ENV=production
JWT_SECRET=<حداقل ۳۲ کاراکتر تصادفی>
SMS_PROVIDER=kavenegar
KAVENEGAR_API_KEY=…
KAVENEGAR_TEMPLATE=…
BAZAAR_ACCESS_TOKEN=…
```

`EXPOSE_OTP=1` در تولید خطا می‌دهد. اگر `JWT_SECRET` را عوض کنید، همه
کاربران از حساب خارج می‌شوند — پس یک بار درست انتخابش کنید.

## ۵. خرید درون‌برنامه‌ای کافه‌بازار ⚠️ سرور آماده، درگاه نه

سمت سرور کامل است و تست دارد: `POST /v1/purchase/verify` رسید را از API
کافه‌بازار می‌پرسد، توکن یک‌بارمصرف است، و تمدید از تاریخ انقضای فعلی
حساب می‌شود. سمت اپ هم وضعیت اشتراک را دیگر خودش نمی‌سازد و از `/v1/me`
می‌گیرد. آنچه مانده، خودِ درگاه است:

- [ ] تعریف محصولات در پنل کافه‌بازار — SKUها باید **دقیقاً** با
      `PLANS` در `backend/src/lib/purchase.ts` یکی باشند:
      `speakup_1w`، `speakup_1m`، `speakup_6m`، `speakup_12m`
- [ ] گرفتن `BAZAAR_ACCESS_TOKEN` از پنل و گذاشتنش در محیط سرور
- [ ] افزودن کتابخانه Poolakey و نوشتن پیاده‌سازی `BillingService`
- [ ] عوض کردن `@Binds` در `DataModule` از `UnavailableBillingService`
      به پیاده‌سازی تازه

> **رسید همیشه سمت سرور سنجیده می‌شود.** `BillingService` عمداً فقط یک
> توکن برمی‌گرداند و هیچ اختیاری برای فعال کردن اشتراک ندارد. اگر روزی
> این مرز شکسته شود، با یک APK دستکاری‌شده اشتراک رایگان می‌شود.
>
> تا وقتی `BAZAAR_ACCESS_TOKEN` تنظیم نشده، سرور در تولید **هیچ** رسیدی
> را نمی‌پذیرد (در توسعه همه را می‌پذیرد تا مسیر قابل تست بماند).

## ۶. تصاویر دروس ۱۱ تا ۳۰ ✅ انجام شد

هر ۶۰۰ تصویر ساخته، بهینه و روی سرور منتشر شده‌اند (۳٫۵۵ دلار، کیفیت low).
اگر روزی محتوا اضافه شد، همین سه دستور:

```bash

./content/publish_images.sh                   # ⚠️ اجباری: انتشار
```

> کلید API را بعد از پایان کار **باطل کنید**.
